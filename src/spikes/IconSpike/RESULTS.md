# IconSpike 検証結果

## Windows 11 Pro (10.0.26200) / .NET 10.0.401 / Avalonia 11.3.22 — 2026-10-02

### 自動計測（`--selftest`、48px、scale=1、サンプル 22 件 → タイル 47 枚）

| 項目 | 結果 |
|---|---|
| 失敗 | 1 件のみ（下記 J3 の「シェル項目リンクのリンク先」）。他は全件取得 |
| Factory 抽出 | 1 件 5〜20 ms が中心。初回呼び出し 130 ms（COM 初期化込み）、.lnk 40〜130 ms、画像ファイル 237 ms |
| SHGetFileInfo 抽出 | 1 件 0.4〜12 ms（Factory より 5〜10 倍速い） |
| png 保存 | 1 件 1〜5 ms |
| **キャッシュ読込** | **1 件 0.3〜0.6 ms、46 枚で合計 15〜20 ms** → ポップアップ表示 100 ms 以内（SPEC §11）はキャッシュ前提なら十分達成可能 |
| STA ワーカー | メッセージポンプ無しの専用 STA スレッドで固まらず完走（J7 OK） |
| URL | `AssocQueryString(http)` で既定ブラウザ（chrome.exe）が取れ、そのアイコンを使える |
| 存在しないパス | `SHGetFileInfo` + `USEFILEATTRIBUTES` で拡張子相当のアイコンが取れる（`.xlsx`、末尾 `\` のフォルダ） |
| 特殊フォルダ | `::{GUID}`（PC・ごみ箱）は Factory で取れる |

### .lnk（J3）

- 通常の .lnk は `IShellLinkW.GetPath` でリンク先が取れる。Office の .lnk は `IconLocation` がリンク先 exe と別ファイル（`...\Installer\{GUID}\xlicons.exe,0` など）＝ **.lnk 自身のアイコンとリンク先のアイコンが異なりうる**。
- 「エクスプローラー」の .lnk はファイルではなくシェル項目を指す（`GetPath` 空、ID リスト → `::{52205FD8-...}`）。このシェル名から Factory でアイコンを取ろうとすると `E_INVALIDARG` で失敗。**.lnk 自身のアイコンは取れる**。

### 目視確認（ユーザー、2026-10-02）

ユーザーの総評は「概ね大丈夫」。個別に指摘があったのは J4 のみ。J1〜J3・J5 はその総評として OK 扱い（.lnk の矢印オーバーレイの有無は個別には聞いていない）。

| # | 結果 | メモ |
|---|---|---|
| J1 画質 | OK | |
| J2 alpha | OK | 暗い背景でも問題の指摘なし |
| J3 .lnk の見た目 | OK | 製品では **.lnk 自身のアイコン**を使う（SPEC §5.4） |
| J4 サムネイル | 方針決定 | 「アイコンのみ」OFF だと Factory は画像を**中身のサムネイル**（縦横比維持、例 48x44）で返し、SHGetFileInfo は常に種類アイコン。ユーザー判断で**画像ファイルは既定でサムネイル**、設定で種類アイコンに切替可（SPEC §5.4 / §7）。フォルダはどちらの方式でも通常のフォルダアイコン |
| J5 D&D した実ファイル | OK | フォルダ等をドロップして取得 OK |

→ 結果は SPEC §5.4（新設）/ §7 / §10.3 に反映済み。

### 気づいた点

- キャッシュヒットだけの再取得でも、画面上の完了まで 1.5 秒かかった。アイコン処理は合計 15 ms なので、残りはスパイク側の UI（ログ TextBox への追記、タイル 1 枚ごとの await）。製品では盤面をまとめて描画する。
